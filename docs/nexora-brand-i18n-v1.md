# NEXORA Brand & i18n Foundation v1

Status: **BRAND FOUNDATION ONLY — NO LIVE TRADING CHANGE**  
Date: 2026-08-18  
Scope: brand identity, trust language, localization terminology, implementation guardrails.

## Safety boundary

This document does **not** change or authorize changes to:

- Premium MTF, Scalp, Pump/Dump signal generation
- strategy/config/radar decision logic
- TP1 / TP2 / TP3 / SL / BE behavior
- Telegram live/result flow
- state / ledger write semantics
- automatic order behavior
- Post-Result / Shadow measurement rules

Brand and localization work must remain a presentation-layer concern unless a separate, measured change is explicitly approved.

# 2. Brand character

NEXORA should feel:

- calm
- premium
- technical but understandable
- transparent
- disciplined
- measured
- trustworthy
- modern

NEXORA should **not** use:

- guaranteed-profit language
- “100% win”, “guaranteed signal”, “risk-free” or similar claims
- fake urgency
- exaggerated success rates without auditable context
- hidden losing outcomes
- casino-like visual language

# 9. Visual identity direction

Recommended direction:

- dark, restrained financial-technology interface
- high contrast and generous spacing
- one primary accent family rather than multiple competing neon colors
- strong uppercase `NEXORA` wordmark
- avoid candlestick/coin clichés in the main logo
- symbol concept: a precise forward-moving `N` / signal-path / measured pulse geometry
- results and health statuses remain functionally clear; branding must never reduce risk/status readability
- Arabic typography and RTL layout receive first-class treatment rather than machine-flipped layout

Brand hierarchy:

**NEXORA**  
*Data. Timing. Discipline.*  
Optional surface label: `CONTROL`, `RADAR`, `RISK`, `SHADOW`, `PERFORMANCE`, `SHARE`, `INSIGHT`.

# 10. Safe implementation order

To minimize regression and unnecessary GitHub Actions use:

### Phase A — foundation
- this brand/i18n specification
- no runtime change

### Phase B — presentation-only shell
- NEXORA wordmark
- tagline
- language selector
- localized public/panel labels
- RTL handling for Arabic
- no trading imports or decision paths touched

### Phase C — share/public surfaces
- branded share cards
- localized result labels
- same underlying trade/result data

### Phase D — trust surfaces
- system health
- measured-performance explanation
- transparent risk disclosure
- “why signal / why no signal” presentation only where source data already exists

Every phase must preserve live signal behavior and be independently rollback-safe.

---

# 11. Acceptance criteria for future integration

A branding/i18n change is acceptable only if:

- Premium / Scalp / Pump live generation remains unchanged
- Telegram/result flow remains unchanged
- TP/SL/BE remains unchanged
- ledger/state writes remain unchanged
- FREE / PREMIUM / ADMIN boundaries remain unchanged
- Turkish still renders correctly
- English renders correctly
- Arabic uses RTL without breaking numbers/symbols
- German renders correctly
- mobile and desktop navigation remain usable
- share cards remain based on real existing trade/result records
- `/healthz` remains healthy
